## Module Map

| Module      | Artifact ID   | Type     | Main Class / Entry Point                                      | Description                                                    |
|-------------|---------------|----------|---------------------------------------------------------------|----------------------------------------------------------------|
| `java-sdk`  | `java-sdk`    | Library  | none (no main)                                                | Public SDK: SPI interfaces (ABTestingProvider, TokenProvider, SchedulerProvider) and request/response model classes. No runtime dependencies beyond Jackson and SLF4J. |
| `commons`   | `commons`     | Library  | none (no main)                                                | Internal shared layer: Temporal workflow interfaces, HBase entities/DAOs (WorkflowHB, NodeHB, WorkflowContextHB), Redis cache (WorkflowCache, NodeDefinitionCache), domain models, and utilities. Depends on java-sdk. |
| `api`       | `api`         | Service  | `com.flipkart.drift.api.bootstrap.DriftApplication`           | Dropwizard HTTP service. Exposes REST endpoints for workflow management (start, resume, terminate, signal), node definitions, and workflow definitions. Talks to Temporal, Redis, HBase. |
| `worker`    | `worker`      | Service  | `com.flipkart.drift.worker.bootstrap.WorkerApplication`       | Dropwizard Temporal worker. Registers Temporal workflow/activity implementations, executes workflow nodes via HTTP calls, manages Redis cache invalidation. Talks to Temporal, Redis, HBase. |
| `examples/worker-flipkart` | `worker-flipkart` | Example | — | Example consumer showing how to extend the worker with custom implementations. Not deployed. |

**Dependency graph (must not be violated):**
```
java-sdk  (no internal deps)
   └── commons  (depends on: java-sdk)
         ├── api     (depends on: commons, java-sdk)
         └── worker  (depends on: commons, java-sdk)
```

## Build Commands

All commands run from the repo root (`/Users/ashwiniborla.vc/Desktop/Flipkart/drift`).

### Full build (all modules, skip tests)
```bash
mvn clean package -DskipTests -pl java-sdk,commons,api,worker -am
```

### Full build with tests
```bash
mvn clean verify -pl java-sdk,commons,api,worker -am
```

### Build a single module (with its upstream deps)
```bash
# api only (also builds java-sdk and commons)
mvn clean package -DskipTests -pl api -am

# worker only (also builds java-sdk and commons)
mvn clean package -DskipTests -pl worker -am

# commons only
mvn clean package -DskipTests -pl commons -am

# java-sdk only
mvn clean package -DskipTests -pl java-sdk -am
```

### Run tests for a single module
```bash
mvn test -pl api -am
mvn test -pl worker -am
mvn test -pl commons -am
mvn test -pl java-sdk -am
```

### Run a specific test class
```bash
mvn test -pl api -Dtest=MyTestClassName -am
```

### Code coverage (JaCoCo)
```bash
mvn verify -pl api,worker,commons,java-sdk -am
# Report: <module>/target/site/jacoco/index.html
```

### Checkstyle / SpotBugs (if configured)
```bash
mvn checkstyle:check -pl api,worker,commons,java-sdk
```

## Golden Rules

1. **Never import across layer boundaries the wrong way.** `java-sdk` must not import `commons`, `api`, or `worker`. `commons` must not import `api` or `worker`. The allowed dependency direction is strictly: `java-sdk` <- `commons` <- `{api, worker}`.

2. **All config comes from environment variables.** Configuration YAMLs use `${ENV_VAR}` substitution via Dropwizard's `EnvironmentVariableSubstitutor`. Never hardcode secrets or host:port in config files.

3. **Structured logging.** Use SLF4J (the `@Slf4j` Lombok annotation) for all logging. Include the correlation ID (`%X{id}`) in log output. Never use `System.out.println`.

4. **HBase access is always via DAO classes.** Direct HBase client calls belong in `commons/persistence/dao/`. Services must not bypass the DAO layer.

5. **Redis cache is eventually consistent.** The cache (WorkflowCache, NodeDefinitionCache) is backed by HBase; invalidation happens via Redis pub/sub. Write operations must go to HBase first, then invalidate cache. Never treat Redis as the source of truth.

6. **Temporal workflows must be deterministic.** No `System.currentTimeMillis()`, no random in workflow code (`GenericWorkflowImpl`). Side effects belong in activities only.

7. **Build with `-am` (also-make).** When building a module, always use `-am` so upstream library modules (java-sdk, commons) are built first. Never build `api` or `worker` in isolation without their transitive deps.

8. **Tests use JUnit 5 unless the test class is in a legacy module.** New tests must use `@ExtendWith(MockitoExtension.class)` not `@RunWith(MockitoJUnitRunner.class)`.

9. **Java 17 only.** Source and target compiler settings are Java 17. No preview features.

10. **Docker images.** Production images are built from `eclipse-temurin:17-jdk-slim-bullseye`. For local dev, the same base image applies. Never pull from Docker Hub unauthenticated in CI.
